# 설치 가이드 — 모니터·키보드·마우스 직접 연결 방식

> 전제: 라즈베리파이 4 모델B 4GB, micro SD 64GB, **모니터(LCD) + USB 키보드 + USB 마우스를 파이에 직접 연결**.
> 헤드리스(SSH만)와 달리 화면에서 부팅 과정과 오류를 눈으로 볼 수 있어, **Wi-Fi가 안 붙는 상황을 바로 고칠 수 있습니다.**
> 소요 시간: 굽기 15분 + 설정 40분 정도.
>
> 같은 폴더의 `설치_가이드_헤드리스.md` 를 대체하는 문서입니다. Step 3(Wi-Fi)·Step 5(파일전송)·Step 9(화면 전환)이
> 헤드리스판과 다르고, 나머지는 같습니다.

---

## ⚠️ 시작 전 — 자격증명 위치 확인

`config.example.yaml` 은 **공개 GitHub 저장소**(`RealPinkRabbit/themango-macros`)에 올라갑니다.
실제 아이디/비밀번호는 이 파일에 넣지 말고, **파이 위의 `/etc/tmg-alert/config.yaml` 에만** 넣으세요.
(설치 스크립트가 `chmod 600` 으로 만들고, 저장소 밖에 있습니다.)

이미 실제 값이 들어간 채로 push 했다면 **더망고 비밀번호를 교체**하세요.

## 준비물 체크

| 항목 | 비고 |
|---|---|
| 라즈베리파이 4 모델B 4GB | |
| **정품 USB-C 전원 어댑터 (5.1V / 3A)** | ★ 저가 어댑터가 24시간 운영 사고 1위. 폰 충전기 비권장 |
| micro SD Pro Endurance 64GB + USB 리더기 | |
| 모니터 + **micro-HDMI 케이블** | ★ 파이4는 일반 HDMI가 아니라 **micro-HDMI**. 전원 포트에 가장 가까운 **HDMI0** 에 꽂아야 기본 출력됩니다 |
| USB 키보드 | 설정 입력용 |
| USB 마우스 | 알림 확인(ACK) 클릭용. 설치 중에는 안 씁니다 |
| 랜선 또는 Wi-Fi | 아래 참고 |
| 유선 스피커 (USB 또는 3.5mm) | Step 9에서. **블루투스는 쓰지 않습니다** |

**네트워크 — 유선 랜을 권합니다 (둘 다 실제로 겪을 수 있는 문제입니다)**

1. 파이4는 **Wi-Fi 2.4GHz와 블루투스가 같은 칩·같은 대역**을 씁니다. BT 스피커를 상시 물려 쓰면 2.4GHz Wi-Fi가 잘 끊깁니다.
2. Trixie 기반 Lite 이미지에서 **첫 부팅 Wi-Fi 연결 실패** 보고가 있습니다.

다만 이 가이드는 모니터가 붙어 있으므로, Wi-Fi가 실패해도 **화면에서 바로 고칠 수 있습니다**(Step 3).
유선이 어려우면 Wi-Fi로 진행하되 **5GHz SSID**를 쓰세요.

## Step 1 — SD 카드 굽기 (노트북)

1. **Raspberry Pi Imager** 설치 → https://www.raspberrypi.com/software/
2. SD 카드를 리더기에 꽂아 노트북에 연결
3. Imager에서 3개를 선택합니다.

| 선택 | 값 |
|---|---|
| 라즈베리파이 장치 | **Raspberry Pi 4** |
| 운영체제 | `Raspberry Pi OS (other)` → **`Raspberry Pi OS Lite (64-bit)`** |
| 저장소 | SD 카드 (용량으로 확인 — ★다른 드라이브를 고르면 그 디스크가 지워집니다) |

> **모니터를 붙이는데 왜 데스크톱판이 아니라 Lite 인가요?**
> 데스크톱판은 상주 프로세스·자동 업데이트·파일 인덱싱으로 SD 쓰기와 RAM을 계속 낭비합니다.
> 24시간 무인 운영에서는 이게 그대로 수명과 안정성 문제가 됩니다.
> 우리에게 필요한 GUI는 **"전체화면 브라우저 하나"** 뿐이고, 설치 스크립트가 그것만(X + openbox + Chromium 키오스크) 따로 깔아 줍니다.
> 그래서 **부팅하면 검은 화면에 흰 글씨 콘솔이 뜹니다. 이게 정상입니다** — 고장이 아닙니다.
> 마우스도 설치가 끝나 알림판이 뜰 때부터 의미가 있습니다.

4. `다음` → "OS 커스터마이즈 설정을 사용하시겠습니까?" → **`설정 편집`**

**일반 탭**

| 항목 | 값 |
|---|---|
| 호스트 이름 | `tmg-alert` |
| 사용자 이름 | `pi` |
| 비밀번호 | 기억할 것 (파이 로그인에 씁니다) |
| 무선 LAN 설정 | **비워두세요.** ★ Step 3에서 화면 보며 직접 잡는 게 훨씬 확실합니다 |
| 로케일 설정 | 시간대 `Asia/Seoul`, 키보드 레이아웃 `us` |

> ★ 로케일(국가) 설정은 빠뜨리지 마세요. 국가가 안 잡히면 규제 문제로 **Wi-Fi 라디오가 소프트 차단(rfkill)** 되어
> "SSID가 하나도 안 보이는" 증상이 납니다.

**서비스 탭**

| 항목 | 값 |
|---|---|
| SSH 사용 | ✅ 체크 (나중에 노트북에서 파일 보내고 로그 볼 때 편합니다) |
| 인증 방식 | `비밀번호 인증 사용` |

**옵션 탭** — `완료 시 미디어 꺼내기` 체크

5. `저장` → `예` → `예` → 굽기 시작 (쓰기+검증 10~15분)

## Step 2 — 첫 부팅 (화면 보면서)

1. SD를 파이에 꽂습니다.
2. **micro-HDMI 케이블을 HDMI0(전원 포트에 가장 가까운 쪽)** 에 꽂고 모니터를 켭니다.
3. USB 키보드·마우스를 꽂습니다.
4. (유선이면) 랜선을 꽂습니다.
5. **마지막에 전원**을 연결합니다.

화면에 무지개 화면 → 흰 글씨가 좍 흐르는 부팅 로그가 지나갑니다.
첫 부팅에서 파일시스템을 확장하고 **한 번 자동 재부팅**하므로, 로그가 두 번 흐르는 게 정상입니다.

2~3분 뒤 이렇게 멈춥니다.

```
tmg-alert login:
```

`pi` 입력 → Enter → Step 1에서 정한 비밀번호 입력 (**입력해도 화면에 아무것도 안 보이는 게 정상**) → Enter

프롬프트가 `pi@tmg-alert:~ $` 로 바뀌면 성공입니다.

### 화면이 안 나올 때

| 증상 | 조치 |
|---|---|
| 모니터가 "신호 없음" | micro-HDMI가 **HDMI0**(전원 쪽)인지 확인. 전원을 끄고 케이블을 꽂은 뒤 다시 켜야 인식되는 경우가 많습니다 |
| 무지개 화면에서 멈춤 | SD 굽기 실패 → 다시 굽기 |
| 초록 ACT LED가 4회/7회씩 반복 깜빡임 | SD를 못 읽는 것 → 다시 굽거나 SD 교체 |
| 빨간 PWR LED가 깜빡임 | **전원 부족** → 정품 5.1V/3A 어댑터로 교체 |
| 키보드 입력이 안 먹힘 | USB 포트를 바꿔 꽂기. 무선 키보드면 동글 인식까지 몇 초 |

## Step 3 — 네트워크 연결 ★ (헤드리스판과 가장 다른 부분)

먼저 지금 상태를 봅니다.

```bash
ip -4 addr show
```

`192.168.0.x` 같은 주소가 보이면 이미 붙은 것이니 **Step 4로 넘어가세요.**
`lo` 만 보이거나 `169.254.x.x` 만 있으면 아직 못 붙은 것입니다.

### Wi-Fi 잡기 — `nmtui` (화면 메뉴 방식, 제일 쉬움)

```bash
sudo nmtui
```

방향키·Enter로 조작합니다.

1. `Activate a connection` 선택
2. 목록에서 **본인 SSID** 선택 → Enter
3. 비밀번호 입력 → `OK`
4. 이름 앞에 `*` 가 붙으면 연결된 것
5. `Back` → `Quit`

확인:

```bash
ip -4 addr show wlan0        # inet 192.168.0.xx 가 나와야 정상
ping -c 3 8.8.8.8            # 인터넷 확인
```

★ **여기 나온 IP 주소를 메모해 두세요.** 노트북에서 파일 보낼 때(Step 5) 씁니다.

### SSID 목록이 아예 안 보일 때

```bash
rfkill list                  # wlan 이 'Soft blocked: yes' 인지 확인
sudo rfkill unblock wifi
sudo raspi-config            # → Localisation Options → WLAN Country → KR
sudo reboot
```

국가(country)가 안 잡히면 규제 때문에 Wi-Fi 라디오가 잠깁니다. 이게 "SSID가 안 보인다"의 가장 흔한 원인입니다.

### 2.4GHz / 5GHz 가 같은 SSID로 묶여 있다면

그대로 두면 2.4GHz에 붙을 가능성이 높고 → **블루투스 스피커와 간섭**합니다. 연결이 잡힌 뒤 대역을 고정하세요.

```bash
nmcli con show                                              # 연결 이름 확인
sudo nmcli con modify "연결이름" 802-11-wireless.band a      # a=5GHz, bg=2.4GHz
sudo nmcli con up "연결이름"
```

> 모니터가 붙어 있으니 5GHz 신호가 약해 끊겨도 화면에서 바로 되돌릴 수 있습니다: `802-11-wireless.band ""`

### 명령줄로 바로 붙이고 싶다면

```bash
nmcli dev wifi list                                  # 주변 SSID 스캔
sudo nmcli dev wifi connect "SSID이름" password "비밀번호"
```

## Step 4 — 상태 점검과 업데이트

```bash
# 1) 기본 확인
hostnamectl                      # OS 버전, 커널
free -h                          # 메모리 (4GB 정도면 정상)
df -h /                          # SD 용량 (64GB 가까이 = 확장 완료)

# 2) ★ 전원 상태 — 24시간 운영에서 제일 중요합니다
vcgencmd get_throttled           # 0x0 이면 정상
vcgencmd measure_temp            # 60도 이하 권장

# 3) 업데이트 (5~15분)
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

> `get_throttled` 가 `0x0` 이 아니면 **어댑터부터 바꾸세요.** 이 상태로 24시간 돌리면
> 원인 모를 멈춤과 SD 손상이 반복됩니다. 다른 걸 고쳐도 소용없습니다.

### 고정 IP (권장)

공유기 관리페이지에서 **DHCP 예약**(MAC 주소에 IP 고정)을 거는 방식이 가장 안전합니다.
파이 설정을 건드리지 않아 나중에 꼬이지 않습니다. MAC은 `ip link show` 로 확인합니다.

## Step 5 — 프로젝트 파일 올리기

세 가지 중 편한 것을 고르세요.

### 방법 A — 노트북에서 SSH 전송 (권장)

Step 3에서 IP가 잡혔고 Step 1에서 SSH를 켰으므로 바로 됩니다. **노트북 PowerShell**에서:

```powershell
cd "C:\Users\sdg08\돈버는클래스 영상\매크로"
scp -r ".\라즈베리파이_주문알림" pi@192.168.0.xx:~/tmg-alert
```

- `192.168.0.xx` 는 Step 3에서 메모한 IP입니다. `tmg-alert.local` 이름은 mDNS가 막힌 환경에서
  **ISP DNS가 엉뚱한 공인 IP를 돌려주는 경우**가 있으니, **IP를 직접 쓰는 편이 확실합니다.**
- 목적지를 `~/tmg-alert` 같은 **영문 이름**으로 지정하세요. 한글 폴더명은 이후 명령이 번거로워집니다.
- 전송량은 100KB 남짓이라 몇 초면 끝납니다.

### 방법 B — 파이에서 git clone

```bash
sudo apt install -y git
git clone https://github.com/RealPinkRabbit/themango-macros.git ~/repo
mv ~/repo/라즈베리파이_주문알림 ~/tmg-alert
```

> 공개 저장소라 로그인 없이 받아집니다. 단, 노트북에서 방금 고친 내용은 **push 한 것만** 반영됩니다.

### 방법 C — USB 메모리

노트북에서 USB에 `라즈베리파이_주문알림` 폴더를 복사한 뒤, 파이에 꽂고:

```bash
lsblk                                    # sda1 등 장치 이름 확인
sudo mkdir -p /mnt/usb
sudo mount /dev/sda1 /mnt/usb
cp -r "/mnt/usb/라즈베리파이_주문알림" ~/tmg-alert
sudo umount /mnt/usb
```

### 확인

```bash
ls -R ~/tmg-alert | head -30
```

## Step 6 — 설치 실행

```bash
cd ~/tmg-alert
sudo bash install/setup.sh
```

10~20분 걸립니다(대부분 Chromium 설치). `1/9 … 9/9` 단계가 화면에 지나갑니다.
하는 일은 패키지 설치, `/opt/tmg-alert` 배치, 파이썬 가상환경, 효과음 생성,
**SD 쓰기 최소화(스왑 제거·저널 RAM화·tmpfs·noatime)**, 워치독, systemd 유닛 등록입니다.
**여러 번 실행해도 안전(멱등)합니다.**

> ★ 헤드리스판과 달리 **키오스크를 끌 필요가 없습니다.** 모니터가 이미 붙어 있으므로
> `tmg-kiosk` 를 그대로 두면 재부팅 후 화면에 알림판이 바로 뜹니다.

## Step 7 — 설정 파일 채우기

```bash
sudo nano /etc/tmg-alert/config.yaml
```

최소한 이 두 줄만 채우면 동작합니다.

```yaml
site:
  login_id: "실제_아이디"
  login_pw: "실제_비밀번호"
```

주기를 바꾸려면 `schedule.market_fetch_min`(가져오기, 기본 5분),
`schedule.badge_watch_sec`(신규 건수 확인, 기본 60초).

저장은 `Ctrl+O` → `Enter`, 종료는 `Ctrl+X`.

```bash
sudo reboot
```

## Step 8 — 동작 확인

재부팅하면 **모니터에 전체화면 알림판**(시계 + 하단 상태바)이 떠야 합니다.

### ★ 알림판이 뜬 뒤 콘솔로 돌아가는 법 (꼭 알아두세요)

키오스크가 `tty1`(첫 번째 콘솔)을 점유하므로, 재부팅 후에는 로그인 프롬프트가 안 보입니다.
**`Ctrl + Alt + F2`** 를 누르면 두 번째 콘솔로 넘어가 로그인할 수 있습니다. (F2~F6 사용 가능)
알림판으로 돌아올 때는 **`Ctrl + Alt + F1`**.

키오스크를 잠시 끄고 싶으면:

```bash
sudo systemctl stop tmg-kiosk       # 잠깐 끄기
sudo systemctl start tmg-kiosk      # 다시 켜기
sudo systemctl disable tmg-kiosk    # 부팅 시 자동 시작 해제
```

### 로그 확인

`Ctrl+Alt+F2` 로 콘솔에 로그인한 뒤:

```bash
systemctl status tmg-agent --no-pager
journalctl -u tmg-agent -f          # Ctrl+C 로 빠져나옴
```

정상이면 이런 흐름이 보입니다.

```
=== tmg-alert 시작 ===
태스크 등록: badge_watch (60초 주기)
태스크 등록: market_fetch (300초 주기)
대시보드: http://0.0.0.0:8080
Chromium 기동: /usr/bin/chromium (DISPLAY=:99)
로그인 시도
로그인 성공
쿠키 12개 동기화
배지 기준선 설정: {'주문관리': 0, 'CS관리': 3, ...}
전체마켓 가져오기 시작
결과 영역 안정 → 완료 판정 (47초)
```

### 테스트 알림

```bash
curl -X POST 127.0.0.1:8080/api/test
```

`Ctrl+Alt+F1` 로 알림판에 돌아가면 화면이 **빨갛게 번쩍이며 "테스트 알림"** 이 떠야 합니다.
(스피커는 아직 안 붙였으니 소리는 안 납니다.) 화면을 클릭하면 해제됩니다.

콘솔에서 해제하려면:

```bash
curl -X POST 127.0.0.1:8080/api/ack
```

### 노트북·폰에서도 보기

같은 네트워크에서 브라우저 주소창에 `http://192.168.0.xx:8080`

### 로그인·배지 파싱을 자세히 보고 싶다면

```bash
sudo systemctl stop tmg-agent
cd /opt/tmg-alert
sudo -u pi DISPLAY=:99 ./venv/bin/python -m tools.probe --config /etc/tmg-alert/config.yaml
sudo systemctl start tmg-agent
```

로그인 → 배지 목록 → 버튼/등록마켓 개수를 순서대로 찍고,
스크린샷과 HTML을 `/dev/shm/tmg-probe/` 에 남깁니다.

---

## ★ Step 8-B — 마우스 커서 보이게 하기 (직접 연결 방식에서만 필요)

기본 설정은 **커서를 숨기도록** 되어 있습니다(키오스크 표준 구성).
`startx ... -nocursor` 옵션과 `unclutter` 데몬 두 곳이 함께 커서를 감춥니다.

클릭 자체는 먹히지만 **포인터가 안 보여서 알림 해제 클릭이 불편**합니다. 마우스를 실제로 쓸 거라면 두 곳을 고치세요.

```bash
# 1) unclutter 비활성화
sudo sed -i 's|^unclutter -idle 0.1 -root &|# unclutter -idle 0.1 -root \&|' /opt/tmg-alert/kiosk/xinitrc

# 2) startx 의 -nocursor 제거
sudo sed -i 's| -nocursor||' /etc/systemd/system/tmg-kiosk.service

sudo systemctl daemon-reload
sudo systemctl restart tmg-kiosk
```

> ⚠️ `install/setup.sh` 를 다시 실행하면 두 파일이 덮어써져 커서가 **다시 숨겨집니다.**
> 재설치할 때마다 이 블록을 다시 실행하세요.
>
> 마우스 없이 쓰고 싶다면 커서는 그대로 두고, 알림 해제는 콘솔에서
> `curl -X POST 127.0.0.1:8080/api/ack` 로 해도 됩니다.

---

## Step 9 — 스피커 연결 (유선)

**블루투스는 쓰지 않습니다.** 파이4는 2.4GHz Wi-Fi 와 블루투스가 같은 칩을 써서 서로 간섭하고,
무엇보다 연결이 끊기면 **소리만 안 나고 시스템은 정상으로 보이는** 조용한 실패가 됩니다.
알림 시스템에서는 이게 가장 나쁜 실패 방식이라, 유선으로 갑니다.

### 9-1. 연결

- **USB 스피커** — 파이 USB 포트에 꽂습니다. 소비 전류가 1.2A 를 넘지 않아야 합니다(4포트 합계 한도).
- **3.5mm 스피커** — 파이의 오디오 잭에 꽂습니다. 앰프 내장(전원 있는) 스피커여야 합니다.
  4극이 아닌 **3극 스테레오 케이블**을 쓰세요(파이4의 잭은 컴포지트 비디오와 공용).

### 9-2. 인식 확인

```bash
pactl list short sinks          # 출력 장치 목록 — 스피커가 보여야 합니다
speaker-test -t sine -f 440 -l 1
paplay /opt/tmg-alert/sounds/order.wav
```

소리가 안 나면 출력 장치가 HDMI 로 잡혀 있을 수 있습니다. 위 목록에서 스피커 이름을 확인해
기본 장치로 지정하세요.

```bash
wpctl status                                   # ID 확인
wpctl set-default <ID>
wpctl set-volume @DEFAULT_AUDIO_SINK@ 80%
```

### 9-3. 설정 (선택)

출력 장치를 확실히 고정하거나, 대시보드의 스피커 표시등을 정확히 만들고 싶을 때만 손대면 됩니다.

```bash
sudo nano /etc/tmg-alert/config.yaml
```
```yaml
notify:
  # 장치를 고정하려면 (이름은 pactl list short sinks 에서 복사)
  play_cmd: "paplay --device=alsa_output.usb-XXXX.analog-stereo {file}"
  # 이 문자열이 든 장치가 있을 때만 '스피커 정상'으로 표시
  sink_match: "usb"
```
```bash
sudo systemctl restart tmg-agent
curl -X POST 127.0.0.1:8080/api/test      # 이번엔 소리까지 나야 정상
```

에이전트는 20초마다 출력 장치가 살아 있는지 확인하고, 2분마다 무음을 흘려
스피커가 절전에 드는 것을 막습니다(액티브 스피커도 무신호가 이어지면 잠드는 제품이 있습니다).

### 9-4. 전력 확인 (USB 스피커일 때)

```bash
curl -X POST 127.0.0.1:8080/api/test      # 실제 볼륨으로 소리를 낸 직후에
vcgencmd get_throttled                    # 0x0 이어야 정상
dmesg | grep -i "over-current"            # 아무것도 안 나와야 정상
```

`0x0` 이 아니면 볼륨을 낮추거나, 스피커 전원만 별도 USB 충전기에서 받으세요.

## 일상 운영

### 코드를 고친 뒤 파이에 반영

노트북 PowerShell에서 (IP는 본인 값으로):

```powershell
cd "C:\Users\sdg08\돈버는클래스 영상\매크로"
scp -r ".\라즈베리파이_주문알림\agent" pi@192.168.0.xx:~/tmg-alert/
ssh pi@192.168.0.xx "sudo rm -rf /opt/tmg-alert/agent && sudo cp -r ~/tmg-alert/agent /opt/tmg-alert/ && sudo chown -R pi:pi /opt/tmg-alert/agent && sudo systemctl restart tmg-agent"
```

설치 스크립트 자체가 바뀌었다면 `sudo bash install/setup.sh` 재실행 (멱등).
단, **Step 8-B의 커서 설정은 다시 적용**해야 합니다.

### 자주 쓰는 명령

```bash
journalctl -u tmg-agent -n 80 --no-pager            # 최근 로그
journalctl -u tmg-agent --since -1h | grep -i error # 최근 오류만
curl -s 127.0.0.1:8080/api/state                    # 현재 상태 JSON
sudo systemctl restart tmg-agent                    # 재시작
sudo poweroff                                       # 종료
```

> ★ 전원을 뽑기 전 반드시 `sudo poweroff`. 이 시스템은 SD 쓰기를 극단적으로 줄여 정전에도 강하지만,
> 종료 시 상태 스냅샷을 한 번 저장하므로 정상 종료가 낫습니다.

### 쓰기량 점검 (한 달에 한 번)

```bash
awk '$3=="mmcblk0" {print $10*512/1024/1024 " MB written"}' /proc/diskstats
```

24시간 간격으로 두 번 재서 증가분이 **하루 수십 MB 이하**면 설계대로 동작하는 것입니다.

## 자주 겪는 문제

| 증상 | 원인 / 조치 |
|---|---|
| 부팅 후 화면이 검은 콘솔뿐 | Lite 이미지라 정상. 설치(Step 6) 후 재부팅해야 알림판이 뜹니다 |
| 재부팅해도 알림판이 안 뜸 | `systemctl status tmg-kiosk` 확인. micro-HDMI가 **HDMI0**(전원 쪽)인지도 확인 |
| 로그인 프롬프트가 안 보임 | 키오스크가 tty1을 점유한 것 → **`Ctrl+Alt+F2`** |
| `tmg-agent` 가 계속 재시작 | `journalctl -u tmg-agent -n 50`. 대개 아이디/비밀번호 또는 네트워크 |
| 로그인 실패 반복 | reCAPTCHA 챌린지 가능성. `/dev/shm/tmg-probe/login_fail.png` 확인 후, 필요하면 사람이 한 번 직접 로그인 |
| 배지를 하나도 못 읽음 | 사이트 상단 메뉴 구조 변경. `tools/probe.py` 로 `poll_page.html` 확인 |
| 소리가 안 남 | `pactl list short sinks` 로 장치 확인 → `wpctl status` 로 기본 장치가 맞는지 |
| 마우스 커서가 안 보임 | 정상 동작(키오스크 기본값). **Step 8-B** 참고 |
| Wi-Fi가 자꾸 끊김 | 2.4GHz 혼잡 → 유선 랜 또는 5GHz 고정(Step 3) |
| 며칠 뒤 멈춤 | `vcgencmd get_throttled` 가 `0x0` 인지(전원), `vcgencmd measure_temp`(발열) |
| 화면 크기가 안 맞음 | `sudo raspi-config` → `Display Options` → 해상도 조정 |
