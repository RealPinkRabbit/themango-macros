# 헤드리스 설치 가이드 (노트북 ↔ 라즈베리파이, 모니터 없이)

> 전제: 빈 micro SD 64GB, 라즈베리파이 4 모델B 4GB, Windows 노트북, LCD는 나중에 연결.
> 설치·파일전송·운영을 전부 노트북에서 SSH로 합니다. LCD는 마지막에 꽂기만 하면 됩니다.
> 소요 시간: 굽기 15분 + 설정 40분 정도.

---

## ⚠️ 시작 전 — 자격증명 위치 확인 (중요)

`config.example.yaml` 에 실제 아이디/비밀번호가 들어가 있습니다. 이 파일은 **`매크로/` 폴더 안에 있고,
`매크로/` 는 공개 GitHub 저장소(`RealPinkRabbit/themango-macros`)로 올라갑니다.** 그대로 두면
비밀번호가 인터넷에 공개됩니다.

권장 처리 (2분)

1. `config.example.yaml` 의 `login_id` / `login_pw` 는 다시 **`"여기에_아이디"` 같은 자리표시자**로 되돌립니다.
2. 실제 값은 **파이 위의 `/etc/tmg-alert/config.yaml` 에만** 넣습니다.
   이 파일은 설치 스크립트가 `chmod 600` 으로 만들고, 저장소에 올라가지 않습니다.
3. 저장소 `.gitignore` 에 `config.yaml` 추가.
4. 이미 push 했다면 **더망고 비밀번호를 바꾸세요.** (커밋 기록에서 지워도 이미 노출된 것으로 취급하는 게 안전합니다)

아래 Step 6에서 실제 값을 파이에 직접 입력하므로, 예시 파일에는 없어도 진행에 아무 지장이 없습니다.

| 항목 | 비고 |

| **정품 USB-C 전원 어댑터 (5.1V / 3A)** | ★ 저가 어댑터가 24시간 운영 사고 1위. 폰 충전기 비권장 |
| micro SD Pro Endurance 64GB + USB 리더기 | |

**왜 유선 랜을 권하나 (두 가지 이유가 겹칩니다)**

1. 파이4는 Wi-Fi 2.4GHz와 블루투스가 같은 칩·같은 대역을 써서, **BT 스피커를 쓰면 2.4GHz Wi-Fi가 잘 끊깁니다.**
2. Trixie 기반 이미지에서 **첫 부팅 시 Wi-Fi가 안 붙는다는 보고**가 있습니다. 헤드리스에서 이게 터지면
   화면이 없으니 원인을 볼 수가 없어 제일 골치 아픕니다.

유선이 정 어려우면 Wi-Fi를 **5GHz 대역 SSID**로 잡으세요. (2.4GHz + BT 조합은 피할 것)

## Step 1 — SD 카드 굽기 (노트북)

1. **Raspberry Pi Imager** 설치 → https://www.raspberrypi.com/software/ (현재 2.x 버전)
2. SD 카드를 리더기에 꽂아 노트북에 연결
3. Imager 실행 후 3개를 고릅니다.

| 선택 | 값 |
|---|---|
| 라즈베리파이 장치 | **Raspberry Pi 4** |
| 운영체제 | `Raspberry Pi OS (other)` → **`Raspberry Pi OS Lite (64-bit)`** |
| 저장소 | SD 카드 (용량으로 확인 — ★다른 드라이브 고르면 그 디스크가 지워집니다) |

> Lite 를 고르는 이유: 데스크톱판은 상주 프로세스·자동 업데이트·인덱싱으로 SD 쓰기와 RAM을 낭비합니다.
> 우리에게 필요한 GUI는 "전체화면 브라우저 하나"뿐이고, 설치 스크립트가 그것만 따로 깔아 줍니다.

4. `다음` → **"OS 커스터마이즈 설정을 사용하시겠습니까?"** → **`설정 편집`** ★ 이 단계가 헤드리스의 핵심입니다.

**일반 탭**

| 항목 | 값 |
|---|---|
| 호스트 이름 | `tmg-alert` |
| 사용자 이름 | `pi` |
| 비밀번호 | (기억할 것 — SSH 로그인에 씁니다) |
| 무선 LAN 설정 | 유선 랜을 쓸 거면 **비워두기**. Wi-Fi를 쓸 거면 아래 설명 참고 |
| 로케일 설정 | 시간대 `Asia/Seoul`, 키보드 레이아웃 `us` |

#### ❓ "무선 LAN — SSID / 비밀번호" 는 무엇을 넣는 칸인가

**파이가 부팅되자마자 접속할 공유기 네트워크의 이름과 비밀번호**입니다. 노트북 설정과는 별개로,
파이에게 "여기로 붙어라"를 미리 알려주는 것입니다.

- Imager가 값을 미리 채워놨다면 **노트북이 지금 연결된 Wi-Fi 정보를 자동으로 가져온 것**이 맞습니다
  (Windows에 저장된 프로필에서 비밀번호까지 읽어옵니다).
- ★ **노트북과 파이는 반드시 같은 네트워크에 있어야 합니다.** 그래야 `ssh pi@tmg-alert.local` 이 됩니다.
- `숨겨진 SSID` 체크는 공유기가 이름을 감춰둔 경우에만.

**2.4GHz와 5GHz가 같은 SSID로 묶여 있는 경우** (공유기의 밴드 스티어링 — 흔한 기본 설정)

SSID만으로는 대역을 고를 수 없습니다. 어느 쪽에 붙을지는 공유기와 파이가 알아서 정하므로,
그대로 두면 2.4GHz에 붙을 가능성이 높고 → **블루투스 스피커와 간섭**이 생깁니다
(파이4는 Wi-Fi 2.4GHz와 BT가 같은 칩·같은 대역을 씁니다).

선택지 세 가지, 권장 순서대로:

| | 방법 | 설명 |
|---|---|---|
| **A (권장)** | **유선 랜** | Wi-Fi 칸을 **전부 비우고** 랜선을 꽂습니다. 간섭 문제도, Trixie 첫 부팅 Wi-Fi 이슈도 한 번에 사라집니다 |
| **B** | **공유기에서 5GHz SSID 분리** | 공유기 관리페이지(보통 `192.168.0.1`)에서 5GHz 대역에 별도 이름(예: `기존이름_5G`)을 부여하고, Imager에 그 이름을 입력 |
| **C** | **일단 붙이고 나중에 5GHz 고정** | 지금 SSID로 진행한 뒤, SSH 접속 후 아래 명령으로 대역을 고정 |

```bash
# C 방법 — 파이에 SSH로 붙은 뒤에 실행 (preconfigured = Imager가 만든 Wi-Fi 연결 이름)
sudo nmcli con modify preconfigured 802-11-wireless.band a   # a=5GHz, bg=2.4GHz
sudo nmcli con up preconfigured
```

> ⚠️ C 방법은 **5GHz 신호가 약한 자리면 아예 접속이 끊겨** 헤드리스에서 손을 못 쓰게 됩니다.
> 파이가 공유기와 가까울 때만 쓰고, 되돌리려면 `802-11-wireless.band ""` 로 비우면 됩니다.
> (그마저 막히면 SD를 노트북에 꽂아 `bootfs` 에서 복구하거나, 유선 랜을 꽂아 들어가면 됩니다)

**서비스 탭**

| 항목 | 값 |
|---|---|
| SSH 사용 | ✅ 체크 |
| 인증 방식 | `비밀번호 인증 사용` |

**옵션 탭** — `완료 시 미디어 꺼내기` 체크

5. `저장` → `예` → `예`(데이터 삭제 확인) → 굽기 시작 (쓰기+검증 10~15분)
6. 끝나면 SD를 뽑기 전에 ★ **아래 "SSH 보험" 을 한 번만 해 두세요.**

### ★ SSH 보험 (30초, 해 두는 걸 권장)

Imager 2.x 일부 버전 + 최신 Lite 이미지 조합에서 **SSH 체크가 실제로 적용되지 않는 사례**가 보고돼 있습니다.
헤드리스에서 이게 터지면 화면이 없어 손을 못 씁니다. 예방은 파일 하나 만들면 끝입니다.

1. 굽기가 끝난 SD를 노트북에 다시 꽂으면 **`bootfs`** (또는 `boot`) 라는 드라이브가 잡힙니다.
   (다른 파티션은 Windows가 못 읽으니 "포맷하시겠습니까?" 가 떠도 **취소**하세요)
2. 그 드라이브 최상위에 **내용이 비어 있고 확장자가 없는 `ssh` 파일**을 만듭니다.

PowerShell (드라이브 문자가 `E:` 인 경우):
```powershell
New-Item -Path "E:\ssh" -ItemType File -Force
```
3. SD를 안전 제거

## Step 2 — 첫 부팅과 SSH 접속

1. SD를 파이에 꽂고, **랜선을 연결**하고, 마지막에 전원을 연결합니다.
2. **3분 정도 기다립니다.** (첫 부팅에서 파일시스템을 확장하고 한 번 재부팅합니다. 초록 LED가
   불규칙하게 깜빡이면 작업 중, 잠잠해지면 준비된 상태입니다)
3. 노트북에서 **PowerShell** 을 열고 접속합니다.

```powershell
ssh pi@tmg-alert.local
```

- 처음 접속하면 `Are you sure you want to continue connecting?` → `yes`
- 비밀번호는 Step 1에서 정한 것

접속되면 프롬프트가 `pi@tmg-alert:~ $` 로 바뀝니다. **여기서부터 모든 작업은 이 창에서 합니다.**

### 접속이 안 될 때

| 증상 | 조치 |
|---|---|
| `Could not resolve hostname tmg-alert.local` | mDNS가 아직 안 뜬 것. 1분 더 기다렸다 재시도. 그래도 안 되면 ↓ |
| 여전히 이름으로 못 찾음 | 공유기 관리페이지(보통 `192.168.0.1`)의 **연결된 기기 목록**에서 `tmg-alert` 의 IP를 확인해 `ssh pi@192.168.0.xx` 로 접속 |
| `Connection refused` | SSH가 안 켜진 것 → SD를 빼서 Step 1의 **SSH 보험**(빈 `ssh` 파일)을 하고 재부팅 |
| `Permission denied` | 비밀번호 오타. 한/영 상태 확인 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 예전 파이 기록과 충돌 → `ssh-keygen -R tmg-alert.local` 후 재접속 |
| 공유기 목록에도 안 보임 | 랜선/전원 확인. Wi-Fi로 시도했다면 **유선으로 바꿔서** 재시도 (Trixie Wi-Fi 이슈 회피) |

## Step 3 — 상태 점검과 업데이트

접속된 SSH 창에서:

```bash
# 1) 기본 확인
hostnamectl                      # OS 버전, 커널
free -h                          # 메모리 (4GB 정도 잡히면 정상)
ip -4 addr show                  # IP 주소 — 메모해 두세요
df -h /                          # SD 용량 (64GB 가까이 잡혀야 정상 = 확장 완료)

# 2) ★ 전원 상태 — 24시간 운영에서 제일 중요합니다
vcgencmd get_throttled           # 0x0 이면 정상. 그 외 값이면 전원 부족/과열
vcgencmd measure_temp            # 60도 이하 권장

# 3) 업데이트 (5~15분)
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

재부팅 후 다시 `ssh pi@tmg-alert.local` 로 접속합니다.

> `get_throttled` 가 `0x0` 이 아니면 **어댑터를 먼저 바꾸세요.** 이 상태로 24시간 돌리면
> 원인 모를 멈춤·SD 손상이 반복됩니다.

### 고정 IP 잡기 (권장)

공유기 관리페이지에서 **DHCP 예약**(MAC 주소에 특정 IP 고정)을 걸어두는 방식이 가장 안전합니다.
파이 쪽 설정을 건드리지 않으니 나중에 꼬일 일이 없습니다. MAC 주소는 `ip link show` 로 확인합니다.

## Step 4 — SSH 키 로그인 (선택, 2분)

매번 비밀번호를 치기 번거롭고, 나중에 자동화 스크립트를 돌릴 때도 편합니다.

**노트북 PowerShell** 에서:

```powershell
# 키가 없다면 생성 (엔터 3번, 암호는 비워도 됨)
ssh-keygen -t ed25519

# 공개키를 파이로 전송 (Windows에는 ssh-copy-id 가 없어서 이렇게 합니다)
type "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh pi@tmg-alert.local "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

이제 `ssh pi@tmg-alert.local` 이 비밀번호 없이 붙습니다.

## Step 5 — 노트북 → 파이 파일 전송

프로젝트 폴더를 통째로 보냅니다. **노트북 PowerShell** (SSH 창 말고 새 창)에서:

```powershell
cd "C:\Users\sdg08\돈버는클래스 영상\매크로"
scp -r ".\라즈베리파이_주문알림" pi@tmg-alert.local:~/tmg-alert
```

- 마지막 `:~/tmg-alert` 처럼 **목적지 이름을 영문으로 지정**하는 게 좋습니다.
  한글 폴더명이 리눅스 쪽에서 깨지면 이후 명령이 번거로워집니다.
- 전송량은 100KB 남짓이라 몇 초면 끝납니다.

확인 (SSH 창에서):
```bash
ls -R ~/tmg-alert | head -30
```

## Step 6 — 설치 실행

**SSH 창**에서:

```bash
cd ~/tmg-alert
sudo bash install/setup.sh
```

10~20분 걸립니다(Chromium 설치가 대부분). 화면에 `1/9 … 9/9` 단계가 지나갑니다.
설치 스크립트가 하는 일은 패키지 설치, `/opt/tmg-alert` 배치, 파이썬 가상환경, 효과음 생성,
**SD 쓰기 최소화 설정(스왑 제거·저널 RAM화·tmpfs)**, 워치독, systemd 유닛 등록입니다.
여러 번 실행해도 안전합니다.

설치가 끝나면 **설정 파일에 실제 값을 넣습니다.**

```bash
sudo nano /etc/tmg-alert/config.yaml
```

최소한 이 두 줄만 채우면 동작합니다.

```yaml
site:
  login_id: "실제_아이디"
  login_pw: "실제_비밀번호"
```

주기를 바꾸고 싶으면 `schedule.market_fetch_min`(가져오기, 기본 5분),
`schedule.badge_watch_sec`(신규 건수 확인, 기본 60초)을 조정합니다.

저장은 `Ctrl+O` → `Enter`, 종료는 `Ctrl+X`.

### LCD를 아직 안 꽂았으므로 — 키오스크는 잠시 꺼둡니다

화면이 없는데 X를 띄우려 하면 5초마다 실패·재시도를 반복합니다(동작에는 지장 없지만 로그가 지저분해집니다).

```bash
sudo systemctl disable --now tmg-kiosk
sudo reboot
```

재부팅 후 SSH로 다시 붙어서:

```bash
# 1) 서비스 상태
systemctl status tmg-agent --no-pager

# 2) 실시간 로그 (Ctrl+C 로 빠져나옴)
journalctl -u tmg-agent -f
```

```
결과 영역 안정 → 완료 판정 (47초)
```

### 노트북 브라우저로 알림판 보기

LCD가 없어도 대시보드는 노트북에서 볼 수 있습니다. 크롬 주소창에:

```
http://tmg-alert.local:8080
```

시계와 하단 상태바(서버/로그인/스피커 점, 미처리 건수, 마지막 가져오기 시각)가 보이면 성공입니다.

### 테스트 알림 쏘기

```bash
curl -X POST 127.0.0.1:8080/api/test
```

브라우저 화면이 **빨갛게 번쩍이며 "테스트 알림"** 이 뜨면 화면 쪽은 끝입니다.
(스피커는 아직 안 붙였으니 소리는 안 납니다) 화면을 클릭하면 원래대로 돌아옵니다.

### 로그인·배지 파싱을 자세히 보고 싶다면

```bash
sudo systemctl stop tmg-agent
cd /opt/tmg-alert
sudo -u pi DISPLAY=:99 ./venv/bin/python -m tools.probe --config /etc/tmg-alert/config.yaml
sudo systemctl start tmg-agent
```

로그인 → 배지 목록 → 버튼/등록마켓 개수를 순서대로 찍어 주고,
스크린샷과 페이지 HTML을 `/dev/shm/tmg-probe/` 에 남깁니다.

**그 결과를 노트북으로 가져오려면** (노트북 PowerShell에서):
```powershell
scp -r pi@tmg-alert.local:/dev/shm/tmg-probe "C:\Users\sdg08\Desktop\probe결과"
```

## Step 8 — 블루투스 스피커 연결 (SSH에서, 화면 없이)

스피커를 페어링 모드로 켜 두고, SSH 창에서:

```bash
bluetoothctl
```

프롬프트가 `[bluetooth]#` 로 바뀌면 한 줄씩:

```
power on
agent on
default-agent
scan on
```

10~20초 기다리면 기기 목록이 흐릅니다. 스피커 이름 옆의 **MAC 주소**(`XX:XX:XX:XX:XX:XX`)를 확인하고:

```
scan off
pair XX:XX:XX:XX:XX:XX
trust XX:XX:XX:XX:XX:XX      ← ★ 자동 재연결의 핵심. 빠뜨리지 마세요
connect XX:XX:XX:XX:XX:XX
quit
```

소리 테스트:

```bash
paplay /opt/tmg-alert/sounds/order.wav
```

들리면 설정에 MAC을 등록합니다.

```bash
sudo nano /etc/tmg-alert/config.yaml
```
```yaml
notify:
  bt_mac: "XX:XX:XX:XX:XX:XX"
```
```bash
sudo systemctl restart tmg-agent
curl -X POST 127.0.0.1:8080/api/test      # 이번엔 소리까지 나야 정상
```

이제 스피커가 절전으로 끊겨도 에이전트가 20초마다 확인해 재연결하고,
2분마다 무음을 흘려 절전 진입 자체를 막습니다.

## Step 9 — LCD 패널 연결 (마지막)

1. 파이 전원을 끕니다: `sudo poweroff` (초록 LED가 완전히 꺼진 뒤 어댑터 분리)
2. **micro-HDMI 케이블을 전원 포트에 가장 가까운 HDMI0 포트**에 꽂습니다. (파이4는 포트가 2개인데 HDMI0만 기본 출력)
3. LCD 전원을 켜고 파이 전원을 연결
4. SSH로 붙어서 키오스크를 다시 켭니다:

```bash
sudo systemctl enable --now tmg-kiosk
```

몇 초 뒤 LCD에 전체화면 알림판이 뜹니다. 확인:

```bash
curl -X POST 127.0.0.1:8080/api/test    # LCD가 빨갛게 번쩍 + 소리
```

화면 크기가 안 맞으면 `sudo raspi-config` → `Display Options` 에서 해상도를 조정합니다.

## 일상 운영 — 노트북에서 하는 작업들

### 코드를 고친 뒤 파이에 다시 올리기

노트북에서 파일을 수정한 뒤, PowerShell에서 두 줄:

```powershell
cd "C:\Users\sdg08\돈버는클래스 영상\매크로"
scp -r ".\라즈베리파이_주문알림\agent" pi@tmg-alert.local:~/tmg-alert/
ssh pi@tmg-alert.local "sudo rm -rf /opt/tmg-alert/agent && sudo cp -r ~/tmg-alert/agent /opt/tmg-alert/ && sudo chown -R pi:pi /opt/tmg-alert/agent && sudo systemctl restart tmg-agent"
```

설치 스크립트 자체가 바뀌었다면 `sudo bash install/setup.sh` 를 다시 돌려도 됩니다(멱등).

### 자주 쓰는 명령

```powershell
# 노트북에서 바로 로그 보기 (SSH 접속 없이)
ssh pi@tmg-alert.local "journalctl -u tmg-agent -n 80 --no-pager"
ssh pi@tmg-alert.local "journalctl -u tmg-agent --since -1h --no-pager | grep -i error"

# 현재 상태 JSON
ssh pi@tmg-alert.local "curl -s 127.0.0.1:8080/api/state"

# 재시작 / 종료
ssh pi@tmg-alert.local "sudo systemctl restart tmg-agent"
ssh pi@tmg-alert.local "sudo poweroff"
```

> ★ 전원을 뽑을 때는 반드시 `sudo poweroff` 를 먼저 하세요. 이 시스템은 SD 쓰기를 극단적으로 줄여
> 갑작스런 정전에도 강하지만, 종료 시 상태 스냅샷을 한 번 저장하므로 정상 종료가 더 낫습니다.

### 쓰기량 점검 (한 달에 한 번 정도)

```bash
awk '$3=="mmcblk0" {print $10*512/1024/1024 " MB written"}' /proc/diskstats
```
24시간 간격으로 두 번 재서 증가분이 **하루 수십 MB 이하**면 설계대로 동작하는 것입니다.

## 자주 겪는 문제

| 증상 | 원인 / 조치 |
|---|---|
| `tmg-agent` 가 계속 재시작 | `journalctl -u tmg-agent -n 50` 확인. 대개 설정의 아이디/비밀번호 또는 네트워크 |
| 로그인 실패가 반복 | 캡차 챌린지 가능성. `/dev/shm/tmg-probe/login_fail.png` 를 노트북으로 가져와 확인 후, 필요하면 사람이 한 번 직접 로그인 |
| 배지를 하나도 못 읽음 | 사이트 상단 메뉴 구조 변경. `tools/probe.py` 로 `poll_page.html` 을 받아 확인 |
| 소리가 안 남 | `bluetoothctl info <MAC>` 의 `Connected: yes` 확인 → `pactl list sinks short` |
| LCD가 까맣다 | `systemctl status tmg-kiosk`, micro-HDMI가 **HDMI0**(전원 쪽)에 꽂혔는지 |
| 며칠 뒤 멈춤 | `vcgencmd get_throttled` 가 `0x0` 인지(전원), `vcgencmd measure_temp`(발열) 확인 |
| SSH가 갑자기 안 됨 | 공유기에서 IP가 바뀐 것일 수 있음 → DHCP 예약 걸기 |
